## Acceptance criteria

1. No unselected audio is enumerated and app launches without broad audio-storage permission. Existing or enqueued automatic/manual full scans cannot run after update; unrelated playlist and cloud contracts still work.
2. A user can select several documents once, restart the app, and find/search/favorite/queue/play successfully granted selected items, without copying or moving originals. Duplicate selection is idempotent; one denied/broken URI does not discard other successful files; unavailable/revoked content has a clear recovery action; removal cannot delete the source.
3. Three primary destinations and Lx Music title match the approved names; optional search behavior is unchanged.
4. All verified obsolete visible/distributed brand marks are replaced by derivatives from the accepted blue-note candidate; notification icon is separate monochrome output. No in-use functional icon or required attribution is removed.
5. Tests/build and each available manual verification pass; unverified device/accessibility scope is reported rather than inferred.

## Compatibility, risk and deliberate retirement

- Deliberately retire MediaStore full-library cataloging, broad audio permission onboarding, storage auto-sync observers, refresh/rebuild/full-rescan controls, and legacy local-folder inclusion/exclusion semantics. User explicitly accepts clearing app data; no migration that reconstructs the old scanned library is in scope. If a schema update is necessary, retain normal Room version-opening correctness without preserving the discarded scanned catalog.
- Retain direct import authority only for the URIs chosen in SAF; document providers may revoke access or expose unsupported/non-seekable files, so unavailable-item handling remains required. Stable numeric song identity and downstream integrations are the main technical risk and must be resolved/tested before UI is connected.
- Retain M3U folder sync, online/cloud source behavior, historical project attribution and stable application identifiers. Screenshot marketing refresh is intentionally deferred until real-device validation.
